# 从零写飞控：路线图

> 面向已有的技术底子：STM32CubeMX + HAL + Keil MDK、FreeRTOS、
> 写过 ADC / CAN / I2C / SPI / TIM 互补 PWM / FOC / INA240 / AS5600。
> 本文只讲**怎么把那些底子搬到穿越机飞控上**，以及会卡在哪。

---

## 0. 先认清一件事：这是两条不同的路

| | 读现成固件 | 自己写 |
|---|---|---|
| 代表 | Betaflight / INAV / ArduPilot | 你自己的工程 |
| 工具链 | **CMake + arm-none-eabi-gcc** | CubeMX + HAL + **Keil** |
| 代码量 | 十几万行 | 几千行起步 |
| 目的 | 学**架构与算法思想** | 学**底层怎么落地** |

**Keil 编译不了 Betaflight**（它是 GCC/Makefile 体系）。所以：
- 想"编译并烧录 Betaflight" → 用官方 `.hex`，或装 GCC 工具链（WSL / MSYS2 / ARM 官方）
- 想"用 Keil 自己写" → 走本路线图

你现有的 `FOCcode/FocTest`（F103 + CubeMX + HAL + Keil + FreeRTOS）
**结构可以直接照搬**成 H743 工程的骨架：`APP/Inc` + `APP/Src` 放业务，
`Core/` 放 CubeMX 生成的初始化。

---

## 1. 开始之前：先做三件事

1. **备份出厂固件** —— 用 STM32CubeProgrammer 读回整片 Flash，存到 `FPVcode/dump/`
   （H743 是 2MB，读回来大概 30 秒）。**没备份就别烧任何东西。**
2. **确认 Flash 分区** —— 看 bootloader 占了几个 128KB 扇区，决定你的固件从哪开始烧（详见硬件文档 §5.7 / §6.6）
3. **确认 IMU 型号** —— 读 `WHO_AM_I`（详见硬件文档 §6.1）。
   这一步没做，后面 SPI 通了也读不出数据，会白折腾半天

## 2. 分阶段路线

每个阶段都有**明确的验收标准**。不要跳阶段——飞控调试最忌讳
"一堆东西都不确定"的时候去查一个问题。

### Stage 0 — 建立调试通路
**做**：CubeMX 建 H743VIT6 工程，开 SWD，点灯（PD10）。
**验收**：Keil 能烧录、能断点、能单步；LED 按代码闪。
**坑**：CubeMX 里 HSE 选 **8 MHz**（本板晶振），别用默认 25MHz。

### Stage 1 — 时钟树 + Cache + 计时基准
**做**：
- 配 PLL：SYSCLK **480MHz**，AXI **240MHz**，APB1/2/3/4 **120MHz**
- 开 **I-Cache 和 D-Cache**（`SCB_EnableICache()` / `SCB_EnableDCache()`）
- 用 **DWT 周期计数器**做微秒级计时（不要用 HAL_Delay 做实时逻辑）

**验收**：DWT 测出的 1 秒和秒表对上；`HAL_GetTick()` 正常。
**H743 特有的坑（后面会反复遇到）**：
- **DTCM（0x2000_0000）不能被 DMA 访问**。DMA 缓冲区必须放
  **AXI SRAM（0x2400_0000）** 或 SRAM1–3（0x3000_0000）
- **D-Cache 和 DMA 会打架**：DMA 写内存后 CPU 可能读到 cache 里的旧值，
  CPU 写内存后 DMA 可能发出旧数据。收发前后要做 cache 维护
  （`SCB_CleanDCache_by_Addr` / `SCB_InvalidateDCache_by_Addr`），
  或者用 MPU 把那块内存设成 non-cacheable
- 这两条是 Cortex-M7 上**最常见的"数据偶尔错一次"的根因**，症状是"大部分时候对，偶尔抽风"

### Stage 2 — IMU 驱动（第一个真正的里程碑）
**做**：
- SPI1 初始化，速度 ≤16 MHz（看 IMU 型号上限），MODE3
- 操作 **PA4 片选**，读 `WHO_AM_I` → 确认型号
- 配置量程（陀螺 ±2000 dps、加速度 ±16g 起步）和输出速率
- 读出一帧 6 轴原始数据

**验收**：静止时加速度计只有一轴 ≈ ±1g，另外两轴 ≈ 0；转动板子数值合理。
**这一刻顺便把硬件文档 §6.3 的"IMU 朝向"一起做了。**
**坑**：HAL 的 `HAL_SPI_TransmitReceive` 有函数调用开销。8kHz 循环里
每帧要读 12–14 字节 + 一次片选翻转，建议直接**寄存器级或 LL 库**写热路径。

### Stage 3 — 姿态解算
**做**：互补滤波或 Mahony 四元数，输出 roll/pitch/yaw。
**验收**：把板子摆成已知角度，解算结果误差 < 2°；快速转动不漂。
**你的优势**：`math_sim` 里的状态空间底子直接用得上——Mahony 就是个
带反馈的观测器。先写互补滤波建立直觉，再上 Mahony。
**坑**：双 IMU 要**先统一到同一机体坐标系**（两路朝向差 180°，见硬件文档 §5.6）。

### Stage 4 — 遥控输入
**做**：接收机接在本板默认的 **UART5（RX=PB5）**。
跑 **CRSF 协议**：解析帧头 + 通道数据，拿到 4 个摇杆量。
**验收**：摇杆动，串口打印出的通道值跟着动。
**坑**：CRSF 是 420000 baud；要先做**帧同步**（找 `0xC8` 帧头 + 长度 + CRC），
别收到第一个字节就开始解析。

### Stage 5 — 电机输出（DShot）
**做**：**DShot300** 起步（比 600 宽容）。
本板默认走 **DShot 位带（bitbang）+ DMA**（`DEFAULT_DSHOT_BITBANG`）：
- 用定时器产生一个 3× 位速率的波形，通过 DMA 送出一串比较值
- 或者用 SPI 以 3× 位速率模拟（一根线，硬件移位天然精确）
- 生成 DShot 帧：11 位油门 + 4 位 CRC（`(value ^ (value>>4) ^ (value>>8)) & 0x0F`）

**验收**：**先不接桨！** 接一个电机，油门推上去能转，松手能停。
**坑**：
- DShot 帧之间要有**至少 2 µs 的空闲**，否则电调认不出帧边界
- 同一组的 4 路（M1–M4）**必须同时更新**，不能一个个发

### Stage 6 — 闭环控制（真正的"飞控"）
**做**：
- 串级 PID：**角速度环（内环，8kHz）** ← **角度环（外环，~1kHz）**
- 先从**纯角速度环（Acro 模式）**开始——只需要陀螺数据，不依赖姿态解算，
  最容易调通
- 混控（Mixer）：4 个电机推力 = 油门 ± roll ± pitch ± yaw 的线性组合

**验收（关键）**：飞机**固定在测试架上**，推油门 + 手动给扰动，
看电机转速能否把姿态拉回来并且不振荡。
> ⚠️ 绝对不要在没通过台架测试的情况下装桨试飞。

**你的优势**：FOC 里的电流环就是串级控制，概念完全一样。
`math_sim` 的 LQR/MPC 底子可以直接拿来算增益。

### Stage 7 — 安全机制（**不能省**）
这一步在很多自研飞控里被跳过，然后炸机：
- **解锁（Arm）逻辑**：摇杆特定组合 + 油门在最低 + 姿态水平，才允许解锁
- **失控保护（Failsafe）**：接收机断连 → 立刻切油门为 0
- **电压保护**：低于阈值 → 报警 / 强制降落
- **看门狗**：主循环卡死 → 复位
- **失控即停**：任何异常（IMU 读失败、传感器超时）→ 立即停电机

**验收**：拔掉接收机电源，电机 1 秒内停。

### Stage 8 — 日志与调参
**做**：通过 UART 或 USB 输出调参接口（照抄 MSP 协议的思路即可）；
关键数据（陀螺、PID 各项、电机输出）记录到 16MB Flash 或串口流。
**验收**：能导出一条飞行日志并在上位机画出来。

## 3. H743 专属坑清单（背下来）

| 坑 | 症状 | 解法 |
|---|---|---|
| DTCM 不能 DMA | DMA 传输永远是 0 或乱码 | 缓冲区放 AXI SRAM (0x2400_0000) |
| D-Cache 与 DMA 不一致 | **偶尔**错一次，难复现 | cache clean/invalidate，或 MPU 设 non-cacheable |
| APB 时钟上限 120MHz | 时钟配到 480 就死机 | SYSCLK 480 / AXI 240 / APB 120，别乱来 |
| 定时器时钟 ≠ APB 时钟 | DShot 位宽算错 | APB 定时器时钟通常是 APB×2 = 240MHz |
| PA15 是 JTDI | JTAG 调试冲突 | **用 SWD，不用 JTAG** |
| 双 IMU 朝向差 180° | 融合后姿态乱跳 | 先统一坐标系再融合 |
| 中断优先级 | 陀螺采样抖动、DShot 帧错位 | 陀螺/电机中断设为最高优先级，且**不要用 HAL_Delay** |

## 5. 与最终目标的衔接

你的长期目标是把 **`hardware/` 的 FOC 电调** 和 **ROS2 避障** 接到穿越机上。
两个切入点：

**A. 用自研 FOC 电调替代成品四合一电调**
硬件文档里的 DShot 输出（Stage 5）就是对接点：
飞控发 DShot → 你的 FOC 电调解析 DShot → 驱动电机。
你已经在 `FOCcode` 里写过 FOC，缺的只是 **DShot 解码**这块。
→ 需要额外实现：双向 DShot 遥测（回传转速），这样飞控端才能用 RPM 滤波。

**B. 让飞控接受外部姿态/位置指令**
在 Stage 8 的调参接口上扩展一条链路：树莓派跑 ROS2 避障 →
通过 UART/CAN 给飞控发**位置/速度设定值**（类似 MAVLink 的
`SET_POSITION_TARGET_LOCAL_NED`），飞控内部跑位置环。
→ 这条路上，ArduPilot 比 Betaflight 更合适（BF 定位是纯手动竞速，
没有位置控制）。**如果这是你的主目标，值得重新评估是不是该基于
ArduPilot 而不是自己从零写。**

## 6. 现实建议

- **Stage 0–3 值得自己写**，你会真正理解飞控的底层
- **Stage 4–6 可以先抄**（读 Betaflight 源码 + 移植），再回头重写
- **Stage 7 绝不能跳**
- 如果目标 A/B 才是重点，**别把时间花在重写 PID 上**——
  用 ArduPilot 当平台，只在它上面做你的增量（FOC 电调 / 避障链路）
